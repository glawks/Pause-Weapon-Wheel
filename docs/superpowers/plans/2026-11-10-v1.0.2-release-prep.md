# v1.0.2 release preparation implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Windows v1.0.2 release reliably discoverable and verifiable by OpenRAC without releasing it yet.

**Architecture:** Keep the existing OpenRAC mod manifest and Windows Actions workflow. The checksum covers the final packaged ZIP and is shipped as a separate Release asset.

**Tech Stack:** JSON, C++20, Windows GitHub Actions/Bash, Python stdlib.

**Spec:** `docs/superpowers/specs/2026-11-10-v1.0.2-release-prep-design.md`

## Global constraints

- Branch: `testing` only; no tag, merge or release.
- Mod ID: `pause-weapon-wheel` unchanged.
- Version: `1.0.2` in manifest and native module.
- SDK: 1.14.2 (mod API 1.14); minimum runtime API in manifest remains 1.12.
- Preserve prior working gameplay and settings behavior.

## Review focus

- Missing checksum asset must fail packaging verification.
- Incorrect archive hash must fail before publication.
- Missing or mismatched version must fail preflight validation.
- A normal push to `testing` must not publish a release.
- A tagged release must still upload all expected assets.

## Task 1: Manifest and native module metadata

**Files:** `tests/release_preflight.py`, `openrac-mod.json`, `src/mod.cpp`.

- [ ] Add a preflight test asserting the requested release version, the exact native module version, and all registered manifest hooks.
- [ ] Run the test to observe the mismatch/missing-hook failures.
- [ ] Update the two versions and append missing hook IDs from the pinned SDK.
- [ ] Re-run the preflight and existing C++ tests; verify all pass.

## Task 2: Reliable checksum packaging

**Files:** `.github/workflows/Windows.yml`.

- [ ] Add a workflow step generating `dist/SHA256SUMS` from `dist/*.zip` and validating it with `sha256sum --check`.
- [ ] Include the checksum in uploaded artifacts and both GitHub Release paths.
- [ ] Verify on an actual Windows test workflow run, which must have `SHA256SUMS` alongside the installable v1.0.2 ZIP.

## Task 3: Publish preparation only

- [ ] Recheck diff, versions, syntax and the branch `testing`.
- [ ] Commit and push only `testing`; monitor Windows workflow completion and verify output artifact contents.
- [ ] Confirm `main` and existing releases are unchanged. Handoff for explicit publishing approval.
